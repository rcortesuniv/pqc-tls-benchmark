# Results dashboard

Generate a self-contained browser dashboard for a completed run:

```bash
analysis/dashboard.py results/pqc-tls-pilot-20260727T100719Z
```

The command refreshes the derived analysis files and writes
`analysis/dashboard.html` inside that result directory. It does not alter raw
JSONL observations, the frozen schedule or integrity evidence.

In Codespaces, the development container starts a dashboard server on port
8000. It selects the newest available result directory by default and
regenerates the dashboard whenever `/dashboard.html` is requested. Rebuild the
container once after pulling the repository change, then use the automatically
forwarded port.

To run the same server manually outside Codespaces:

```bash
python3 analysis/dashboard_server.py --bind 0.0.0.0 --port 8000
```

Open `/dashboard.html` through the forwarded port. Use the group, RTT and loss
filters to examine condition summaries. The dashboard aggregates batch-cell
medians for display; its contrast table retains the batch-aware intervals and
Holm-adjusted values generated by `summarise.py`.

When more than one result directory under `results/` has generated analysis
output, a **Run** selector appears next to the validation badge listing every
servable run, newest first. Choosing one loads `/dashboard.html?run=<name>`;
the same URL can be shared or bookmarked directly. Requesting an unknown or
no-longer-servable run name falls back to the newest available run and shows
a notice explaining why.
